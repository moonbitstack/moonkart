Eight steps

  1. Put something in
  2. Bound the box
  3. Let it expire
  4. Load it once
  5. When a load fails
  6. Read the counters
  7. Answer, then reload
  8. Outlive the process
01 / PUT

Put something in

A cache is built by a constructor, not by a type. Choose the policy in the name: tinylfu_cache, lru_cache or s3fifo_cache. They all return the same Cache[K, V], so the rest of your code never mentions which one you picked.

let cache = @moonkart.tinylfu_cache(cap=1000)
cache.set("user:128", "Leo")
match cache.get("user:128") {
  Some(name) => println("read user:128 -> \{name}")
  None => println("read user:128 -> nothing")
}

WHAT IT PRINTS

read user:128 -> Leo
02 / BOUND

Bound the box

By default the cache holds cap entries. When the values are not all the same size, give a weigher and a max_weight instead; the cache keeps the total weight under the limit and evicts by the same policy.

let by_weight = @moonkart.lru_cache(
  max_weight=12L,
  weigher=fn(_k : String, v : String) { v.length().to_int64() },
)
by_weight.set("foo", ".foo{}")  // 6
by_weight.set("emm", ".emm{}")  // 6 + 6 = 12
by_weight.set("bar", ".bar{}")  // 18 > 12, so "foo" leaves
println("foo=\{by_weight.contains("foo")} emm=\{by_weight.contains("emm")} bar=\{by_weight.contains("bar")}")

WHAT IT PRINTS

foo=false emm=true bar=true
03 / EXPIRE

Let it expire

ttl counts from the moment an entry is written; tti counts from its last read. For anything else — a deadline that depends on the value, or one that only some entries get — pass an Expiry with your own callbacks.

A single write can carry its own deadline instead: expire_after outranks the cache's rule, and no read moves it.

The clock is a parameter. Nothing in the library reads the wall clock, so a test moves a number instead of sleeping.

let now : @ref.Ref[Int64] = @ref.Ref(0L)
let timed = @moonkart.lru_cache(
  cap=8L,
  expiry=@moonkart.ttl(10L),
  clock=fn() { now.val },
)
timed.set("user:7", "Vega")                    // the cache's 10
timed.set("user:9", "Nova", expire_after=20L)  // its own 20
println("at t=0:  \{timed.contains("user:7")} \{timed.contains("user:9")}")
now.val = 11L
println("at t=11: \{timed.contains("user:7")} \{timed.contains("user:9")}")

WHAT IT PRINTS

at t=0:  true true
at t=11: false true
04 / LOAD

Load it once

get_with runs the loader only on a miss and stores what it returns. Ask twice for the same key and the second call is a plain hit — the loader does not run again.

The loader may raise. Wrap one that cannot fail with infallible_loader and the call site needs no error handling.

let loaded = @moonkart.lru_cache(cap=8L)
let calls : @ref.Ref[Int] = @ref.Ref(0)
let load = fn(_k) raise {
  calls.val = calls.val + 1
  if calls.val > 9 { fail("too many calls") }
  "Leo"
}
let first = loaded.get_with("user:128", load)
let second = loaded.get_with("user:128", load)
println("\{first} then \{second}, loader ran \{calls.val} time(s)")

WHAT IT PRINTS

Leo then Leo, loader ran 1 time(s)
05 / FAIL

When a load fails

An error from the loader reaches the caller and leaves nothing behind. The next call is a miss again, so a database that comes back up is picked up without clearing anything.

let failing : @moonkart.Cache[String, String] =
  @moonkart.lru_cache(cap=8L)
let mut failed = false
let _ = failing.get_with("class:foo", fn(_k) raise {
  fail("no such rule")
}) catch {
  _ => { failed = true; "" }
}
println("failed load -> error=\{failed}; stored=\{failing.contains("class:foo")}")

WHAT IT PRINTS

failed load -> error=true; stored=false
Concurrent readers. In @moonkart/concurrent, readers of the same key share one loader. When it fails they all receive that error, and nothing is cached, so the next call tries again. ShardedCache splits the key space over independent caches, so traffic in one shard cannot evict another's entries.
06 / COUNT

Read the counters

stats() returns the counts kept while the cache runs: hits, misses, evictions, and how long loading took. hit_rate() is derived from the first two.

let counted = @moonkart.lru_cache(cap=8L)
counted.set("user:128", "Leo")
ignore(counted.get("user:128"))
let s = counted.stats()
println("hits \{s.hit_count}, misses \{s.miss_count}")

WHAT IT PRINTS

hits 1, misses 0
Removal listener. Pass one at construction and every entry that leaves reports why: Capacity, Expired, Explicit or Replaced.
07 / RELOAD

Answer, then reload

A value that took a minute to work out should not cost a miss every time it is asked for. Give the asynchronous cache a refresh window: a value older than the window answers the read at once, and the loader runs behind it. The window is measured from the write, so nobody has to remember when the value arrived.

let clock_now : @ref.Ref[Int64] = @ref.Ref(0L)
let polled = @concurrent.AsyncCache::new(
  @moonkart.lru_cache(cap=8, clock=fn() { clock_now.val }),
  refresh=@concurrent.refresh_every(60_000_000_000L), // an hour, in nanoseconds
)
let runs : @ref.Ref[Int] = @ref.Ref(0)
let report = async fn(_id : Int) -> String {
  runs.val = runs.val + 1
  "report #\{runs.val}"
}
ignore(polled.get_with(7, report))     // a miss: the loader runs
clock_now.val = 60_000_000_000L       // an hour later the value is stale
let stale = polled.get_with(7, report)  // answered, and reloaded behind the read
let before = runs.val
polled.settle()                        // run what is waiting
let fresh = polled.get(7).unwrap()
println("\{stale}, then \{fresh}: the loader ran \{before} time(s) during the read, \{runs.val} by the end")

WHAT IT PRINTS

report #1, then report #2: the loader ran 1 time(s) during the read, 2 by the end
One reload per key. A second reader that finds the same key stale joins the reload already running instead of starting another, and a reload that raises keeps the old value and calls refresh.on_failure. Hand the cache a way to start a task (spawn=fn(task) { group.spawn_bg(task) }) and it runs the reloads itself; without one they wait for settle. The synchronous cache never refreshes: it has nowhere to run the task.
08 / OUTLIVE

Outlive the process

Memory is the first tier. DiskCache puts a bounded file behind it: every write appends a record, a read that misses memory is answered from the file and put back, and the file has a budget of its own. When that budget is spent, the record that has been seen least often is the one that goes, so a scan of one-off keys cannot walk the file clean.

async fn keep(path : String) -> Unit raise {
  let disk = @disk.DiskCache::open(
    @moonkart.lru_cache(cap=8),
    path,
    fn(key : String) { @utf8.encode(key) },
    fn(bytes) { Some(@utf8.decode_lossy(bytes)) },
    fn(value : String) { @utf8.encode(value) },
    fn(bytes) { Some(@utf8.decode_lossy(bytes)) },
    max_bytes=64L, // room for three 16-byte records
  )
  disk.set("draft", "one")
  disk.set("draft", "two")   // the same key again: seen twice
  disk.set("scan-1", "x")
  disk.set("scan-2", "y")
  disk.set("keep-me", "z")  // seen once, and the budget is spent
  let s = disk.stats()
  println("the file holds \{s.entries} records in \{s.bytes} bytes, \{s.denied} turned away")
  println("keep-me is in memory: \{disk.contains("keep-me")}")
  let again = @disk.DiskCache::open(@moonkart.lru_cache(cap=8), path,
    fn(key : String) { @utf8.encode(key) }, fn(bytes) { Some(@utf8.decode_lossy(bytes)) },
    fn(value : String) { @utf8.encode(value) }, fn(bytes) { Some(@utf8.decode_lossy(bytes)) },
    max_bytes=64L)
  println("after reopening, keep-me is there: \{again.contains("keep-me")}")
}

WHAT IT PRINTS

the file holds 3 records in 49 bytes, 1 turned away
keep-me is in memory: true
after reopening, keep-me is there: false
In a browser. @moonkart/storage is the same contract over a store of strings: local_storage() binds the browser's own, the rules for budget, eviction and admission are the file's, and watch() drops this page's copy of a key when another tab writes it. admission=@policy.TakeAll keeps everything that fits instead of deciding by how often a key was seen.
