Types and methods

struct Cache[K, V]
A bounded cache generic over key K and value V. The eviction strategy is erased behind the open Policy contract, so one Cache type serves every strategy; new accepts a third-party policy without changing this type. The default strategy, chosen by tinylfu_cache, is W-TinyLFU; lru_cache and s3fifo_cache provide the other shipped strategies.
fn[K : Eq + Hash, V] Cache::contains(Self[K, V], K) -> Bool
Whether key is present and not expired. Expired entries are purged and report as absent. This is a presence check: it neither refreshes a time-to-idle deadline nor counts a hit.
fn[K : Eq + Hash, V] Cache::entry(Self[K, V], K) -> Entry[K, V]
Returns a snapshot of the entry for key. Panics if the key is absent or expired; prefer entry_or_null when absence is expected.
fn[K : Eq + Hash, V] Cache::entry_or_null(Self[K, V], K) -> Entry[K, V]?
Returns a snapshot of the entry for key, or None. The snapshot is a copy detached from the cache.
fn[K : Eq + Hash, V] Cache::get(Self[K, V], K) -> V?
Returns the value for key, or None if absent or expired. A successful read counts a hit and bumps the entry's recency; an expired or missing read counts a miss.
fn[K : Eq + Hash, V, E : Error] Cache::get_with(Self[K, V], K, (K) -> V raise E, expire_after? : Int64) -> V raise E
Returns the value for key. On a miss, runs loader(key) and stores the result. The loader may raise; a raised error is not cached, is counted as a load failure, and is handed to the caller unchanged. expire_after does to the loaded value what it does to set.
fn[K : Eq + Hash, V] Cache::insert(Self[K, V], K, V, expire_after? : Int64) -> V?
Inserts or replaces key and hands back the value it displaced, which is None when the key was not there. This is set with the old value returned, for a caller that has to undo or account for what it replaced; the removal listener still hears about the replaced value as Replaced. expire_after means what it means on set.
fn[K : Eq + Hash, V] Cache::invalidate(Self[K, V], K) -> Bool
Removes key explicitly (alias of remove). Returns whether it was present.
fn[K : Eq + Hash, V] Cache::invalidate_all(Self[K, V]) -> Unit
Removes every entry, reporting each to the removal listener as Explicit.
fn[K : Eq + Hash, V] Cache::invalidate_if(Self[K, V], (K, V) -> Bool) -> Int64
Removes every entry for which pred(key, value) is true. Returns the number removed.
fn[K, V] Cache::now(Self[K, V]) -> Int64
The clock's current reading — the one the cache compares deadlines and write times against.
fn[K : Eq + Hash, V] Cache::peek(Self[K, V], K) -> V?
Returns the value for key without recording a hit or a miss, moving the entry's place in the eviction order, or restarting a time-to-idle deadline. An entry past its deadline is dropped and reported as Expired, as it is on any other read, so a peek never answers with a dead value. Use it to look at an entry without changing what the cache will evict next: a metrics sweep, a debug view, or a check made on the side of a read that is counted elsewhere.
fn[K, V] Cache::policy_size(Self[K, V]) -> Int32
Number of entries the eviction policy currently tracks (equals size).
fn[K : Eq + Hash, V] Cache::purge_expired(Self[K, V]) -> Int64
Drops every entry whose deadline has passed, reports each to the removal listener as Expired, and returns how many went. Expiry is otherwise lazy: an entry past its deadline is dropped when something asks for it. An entry nobody asks for again keeps its space and its place in the policy's order until then, which is why a cache that writes more than it reads needs this sweep. Counters are untouched: a sweep is housekeeping, not a read.
fn[K : Eq + Hash, V] Cache::remove(Self[K, V], K) -> Bool
Removes key explicitly. Returns whether it was present.
fn[K : Eq + Hash, V] Cache::set(Self[K, V], K, V, expire_after? : Int64) -> Unit
Inserts or replaces key. A replaced value is reported to the removal listener as Replaced; an insertion calls after_update when the key was already present, otherwise after_create. expire_after fixes this entry's deadline at expire_after nanoseconds from now, for this write only: the cache's own rule does not apply to it, and a later read will not move the deadline it computed. Write the entry again without it to hand the entry back to the cache's rule.
fn[K, V] Cache::size(Self[K, V]) -> Int64
Number of entries currently stored.
fn[K, V] Cache::stats(Self[K, V]) -> CacheStats
A copy of the running counters.
fn[K, V] Cache::to_array(Self[K, V]) -> Array[(K, V)]
A snapshot of every live entry as (key, value) pairs, in no particular order. Useful for persistence and for tests.
fn[K : Eq + Hash, V, E : Error] Cache::try_get_with(Self[K, V], K, (K) -> V? raise E, expire_after? : Int64) -> V? raise E
Like get_with, but loader may return None to signal "no value"; such a result is not cached and None is returned. A raised error propagates to the caller and is counted as a load failure.
fn[K, V] Cache::weight(Self[K, V]) -> Int64
The total weight of the entries the cache holds, which is what a weigher budgets against. Without a weigher every entry weighs one, so this equals size. The figure is added up over the entries on each call rather than kept as a running total, so it is a report and not a hot-path call. Entries whose deadline has passed still count until something removes them: call purge_expired first to report what is live.
fn[K : Eq + Hash, V] Cache::written_at(Self[K, V], K) -> Int64?
The clock reading at which the live value for key was written, or None if the key is absent or expired. A write of any kind counts, so a value the caller stored and a value a loader produced age the same way.
struct CacheStats
Counters the cache keeps while it runs. The raw counts are exposed so callers can aggregate them; hit_rate and miss_rate are derived.
fn CacheStats::hit_rate(Self) -> Double
Fraction of reads that hit, in 0.0 ..= 1.0. Zero reads reports 0.0 rather than dividing by zero.
fn CacheStats::merge(Self, Self) -> Self
Two sets of counters added together, for a cache split into shards or a report built from several caches.
fn CacheStats::miss_rate(Self) -> Double
Fraction of reads that missed, in 0.0 ..= 1.0.
struct Config[K, V]
The cross-cutting knobs of a cache, bundled so they can be built once and reused across caches. Capacity lives on the eviction policy, not here. default_config fills in every knob; write the record out when one of them differs, and hand the result to new_with_config.
struct Entry[K, V]
An entry as seen by a reader: its value, weight and absolute expiry deadline (if any).
enum EvictionReason
Why an entry left the cache.
struct Expiry[K, V]
Per-entry lifetime policy. Each callback returns an absolute nanosecond deadline, or None to leave the existing deadline untouched (when the callback does not apply) or to let the entry live until capacity eviction (on create). after_read and after_update receive the current deadline so they can extend or keep it. A pure time-to-live from creation uses ttl; a time-to-idle (idle) lifetime uses tti; anything else is expressed with the three callbacks directly.

type Clock = () -> Int64

struct AsyncCache[K, V]
An asynchronous handle around a cache. Loads are coalesced per key: while one task is computing a value for a key, other tasks asking for the same key wait for that computation instead of starting their own; tasks asking for other keys never wait on it. No lock is held while the loader runs. The only shared mutable state is the in-flight table, whose reads and writes are synchronous, so under the cooperative scheduler they never interleave. The first task to miss records a per-key Lazy, releases the scheduler by awaiting it, and the loader runs outside any shared critical section.

struct Refresh[K]
When a value should be reloaded, and who hears about a reload that failed. A value older than after still answers a read, and the loader runs behind the read to replace it. The same key has one reload in flight at a time, and a reload that raises leaves the old value in place and reports the error to on_failure. None never refreshes on its own: the value stays until it expires or is evicted. Only the asynchronous cache acts on this. The synchronous cache answers a read and returns, with nowhere to run a reload, so a value there changes only when something writes it.
struct ShardedCache[K, V]
A cache split into independent shards, each with its own entries, its own eviction budget and its own in-flight table. A key always lands in the same shard, so a read or a write behaves exactly as it does on a single cache; what changes is that traffic in one shard cannot evict entries in another, and a slow loader in one shard holds up nothing in the others. The shard is hash(key) modulo shards, so the split is stable across calls and across processes only as far as the runtime's hash seed is. The runtime schedules tasks cooperatively, so sharding is not by itself a speed-up: it is the unit a caller can hand to its own threads, and the unit that keeps unrelated workloads from pushing each other out.

struct S3Fifo
S3-FIFO-inspired second-chance FIFO: a single FIFO queue with a visited bit per entry. When the queue is over budget, an entry that has been read since it entered is moved back to the tail with its bit cleared, while an entry never read since it entered is evicted. Scan floods and one-hit wonders are evicted on first sight, while repeated keys survive several rounds, at the cost of one boolean per entry.

struct Sketch
A frequency sketch: four rows of 4-bit counters, sized from the number of entries the caller wants to remember, with the whole table halved once the sample window fills. It answers "how often has this key been seen lately" from a hash alone, so a key keeps its history after it leaves and comes back. The shape follows the sketch behind TinyLFU, as Caffeine and moka implement it: a counter per entry per row (four rows, four times the capacity rounded up to a power of two), counters saturating at 15, and a reset that halves every counter every 10 × capacity records. The reset is what keeps the estimate about recent traffic rather than the whole history.
fn Sketch::age(Self) -> Unit
Halves every counter and the sample count. record runs this when the window fills; calling it directly forgets old traffic at once.
fn Sketch::estimate(Self, Int32) -> Int32
The estimated frequency of the key whose hash is hash: the smallest of its four counters, which is the estimate the collisions cannot inflate.
fn Sketch::new(Int32) -> Self

fn Sketch::record(Self, Int32) -> Unit

disk

A memory cache and a bounded file behind it, for the native target.

Native only: the filesystem in the standard library is asynchronous and native-only. storage offers the same contract on the js target.

Types and methods

struct DiskCache[K, V]
A cache backed by both memory and a file. The memory cache answers reads; the file holds a record for every write it keeps, so the cache survives a restart, and the file is itself bounded: max_bytes caps the live records, and when a write would spend the last of the budget the rule in admission decides whether the newcomer or a resident record leaves. Keys and values are encoded with codecs you supply, so the layer stays generic and imposes no wire format of its own. Records restored on open are replayed through set, so the memory cache's current capacity and expiry policy apply to them, and they count as written when the cache opens: a record on the file carries no write time, so a refresh window starts again after a restart. Call compact periodically so the file does not grow without bound.

storage

The same second tier over a store of strings, such as the browser's localStorage.

local_storage() and StorageCache::watch exist on the js target only, where they bind localStorage and its storage event.

Types and methods

struct StorageCache[K, V]
A cache backed by both memory and a store that outlives the page: the same contract as the file tier, on a medium that is a map of strings. Every write goes to memory and to the store, bounded by max_bytes over the record bytes, with the rule in admission deciding who keeps the last byte. A read that misses memory is answered from the store and put back into memory. Records found on open are restored in the store's own order and the memory cache's current capacity and expiry policy apply to them; a stored record carries no write time, so a restored value counts as written when the page loads.

Drops a key this page still holds because another page wrote it: the memory entry goes, the store's newer value stays, and the next read takes it. Returns whether the storage key belonged to this cache. A storage event listener passes it the key of every write another tab makes, which is what StorageCache::watch wires up in a browser.

struct Record
Where a medium keeps one record, and how many bytes it takes there. slot is the medium's own address: the file tier's offset, or zero for a medium that finds a record by its key.
struct Stats
What a second tier has done since it was opened. entries and bytes describe the live records, not the size of the medium: a medium that appends keeps the space of superseded and deleted records until it rewrites itself.
struct Tier[K]
The keys a slower medium holds, with the bookkeeping the two-tier caches share: an index of record sizes and addresses, a least-recently-used order, a frequency sketch and a byte budget. Each method that can free room returns the keys to delete from the medium, so the caller keeps the only copy of the medium's own rules. Copies of the value share one set of bookkeeping, so a handle can be passed by value.
