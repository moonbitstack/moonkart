new_tinylfu(cap? : Int64, max_weight? : Int64, window_ratio? : Double, protected_ratio? : Double) -> Tinylfu
Creates a W-TinyLFU policy. `window_ratio` sizes the admission window; `protected_ratio` sizes the protected segment of the main region.
tinylfu_protected_ratio : Double
Fraction of the main region given to the protected segment in W-TinyLFU. Entries read at least once are promoted here, away from the probation queue.
tinylfu_window_ratio : Double
Fraction of capacity given to the admission window in W-TinyLFU. The window admits new entries before they must earn a place in the main region, so a burst of one-hit wonders does not evict the working set.

S3Fifo::admit(Self, Int64, Int64, Int32) -> Array[Int64]
S3-FIFO-inspired second-chance FIFO: a single FIFO queue with a `visited` bit per entry. When the queue is over budget, an entry that has been read since it entered is moved back to the tail with its bit cleared, while an entry never read since it entered is evicted. Scan floods and one-hit wonders are evicted on first sight, while repeated keys survive several rounds, at the cost of one boolean per entry.

Tinylfu::admit(Self, Int64, Int64, Int32) -> Array[Int64]
W-TinyLFU policy: a small admission window feeds a segmented LRU (probation and protected) that is guarded by a frequency sketch keyed by the entry's key hash, so often-read keys survive even after they age out of recency. This is the cache's default strategy.
