Put one in, then click a card in the box to ask for it again.

01 / CAPACITY

Bounded

Cap by entry count with cap, or by total size with max_weight and a weigher when values differ.

02 / TIME

Expires

Time to live, time to idle, or a rule of your own, per entry. The clock is a parameter, so a test moves a number instead of sleeping.

03 / LOADING

Loads once

Readers of the same missing key wait for one loader and share its answer. If it raises, every reader gets that error and nothing is stored.

04 / POLICY

Swappable

W-TinyLFU by default, LRU and S3-FIFO when you want them, and your own behind the same contract. The cache type never changes.

05 / FRESHNESS

Refreshes behind a read

A value past its window still answers, while the loader runs behind the read. One reload per key, and a failed one keeps what you had.

06 / TIERS

Outlives the process

A second tier on a file or in browser storage, bounded in bytes, admitting by how often a key is seen, restored when the process starts.

SIX CALLS, ON A BOX THAT HOLDS FOUR

let cache = @moonkart.lru_cache(cap=4L)
cache.set("a", 1)
cache.set("b", 2)
cache.set("c", 3)
cache.set("d", 4)
let a = cache.get("a")  // "a" is now the most recent
cache.set("e", 5)   // full: "b" leaves

println("a is present: \{cache.contains("a")}")
println("read a: \{a.unwrap_or(-1)}")
println("b survives: \{cache.contains("b")}")
println("e is present: \{cache.contains("e")}")
let s = cache.stats()
println("hits: \{s.hit_count}, misses: \{s.miss_count}")
println("evictions: \{s.eviction_count}")
